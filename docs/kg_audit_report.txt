================================================================================
kgav — KNOWLEDGE GRAPH AUDIT REPORT
A Biolink-conformant knowledge graph for antiviral drug repurposing across
Coronaviridae and Flaviviridae, and what it can and cannot be used to measure.
================================================================================

Repository      github.com/vivekyaadav/kgav
Schema version  0.13.0
Release audited v0.1
Scope           16 viruses — 7 Coronaviridae, 9 Flaviviridae

HOW TO READ THIS FILE. Structural facts (classes, predicates, metapaths,
layers, sources) are pinned by tests/test_kg_audit_report.py against the
schema, the pipeline and the register, so they cannot drift from the code
without a test failing. Release-dependent COUNTS are deliberately not
restated here; they live in one place:

    make audit                     # per-layer, per-virus, what is missing
    make check-results             # every results file against the graph

Release COUNTS are in section 4 and are GENERATED from the release,
stamped with its content hashes, and checked by the same test. Any other
figure here that a rebuild could move is marked with the run it came
from. This project has shipped two reports that quoted a figure from a
previous graph, which is why none of this is left to hand-editing.


================================================================================
1. WHAT THE GRAPH IS FOR
================================================================================

One question, asked two ways.

The FIRST question is "which existing drug works against this virus". It
needs antiviral activity labels, and it is the question the evaluation in
docs/evaluation.md failed to answer honestly: 92.2% of labelled compounds
share a publication between the evidence edge and the label it was
supposed to predict, so a scorer is partly reading its own answer sheet.
The result on this release is that 11 of 15 scored viruses have no
readable reasoning channel at all and 2 readable cells in the whole
table are significant uncorrected -- of which 1 survives the loosest
correction family.

The SECOND question is "where does the drugged human proteome overlap
what this virus depends on". It touches no label predicate, so the
shared-publication confound has nothing to attach to. That is the
pathway-analysis question, and section 7 is about it.

The graph is built so that the second question can be asked without the
first contaminating it. Four predicates are HELD OUT of every metapath
and are never evidence:

    HAS_ANTIVIRAL_ACTIVITY_AGAINST   SmallMolecule -> OrganismTaxon
    MEASURED_INACTIVE_AGAINST        SmallMolecule -> Protein
    TREATS                           SmallMolecule -> Disease
    IN_TRIAL_FOR                     SmallMolecule -> Disease

Three of those are evaluation labels — the ground truth being predicted.
MEASURED_INACTIVE_AGAINST is the NEGATIVE label and is held out for the
same reason: it is answer sheet, not feature.


================================================================================
2. ARCHITECTURE
================================================================================

Three stages, deliberately separated: INGEST -> ASSEMBLE -> SERVE. Each
stage writes something a human can read and a test can check, and no
stage reaches past the one before it.

    data/raw/*            sources as they arrived, with sidecar
      |                   provenance (URL, date, checksum). Gitignored:
      |                   large, and reconstructible from the sidecars.
      v
    INGEST                12 independent layers (section 6). Each is a
      |                   script in scripts/ plus a library module in
      |                   src/kgav/, and each writes its OWN release
      |                   directory of nodes.jsonl / edges.jsonl.
      v
    ASSEMBLE              assemble.py merges the layers under a declared
      |                   precedence and writes MANIFEST.json.
      v
    data/releases/v0.1    nodes.jsonl + edges.jsonl + MANIFEST.json
      |
      +---> SCORE         baselines, calibration, temporal split,
      |                   pathway landscape -> data/results/*.json,
      |                   each stamped with the release hash
      |
      +---> SERVE         the agent: orchestrator -> guards -> tools ->
                          verify

WHY LAYERS ARE INDEPENDENT. A source that fails, or arrives late, or
turns out to be unreadable blocks only its own layer. Each layer's
output is separately inspectable, so "what did VirHostNet actually
contribute" is a question with a file as its answer rather than a diff.
It is also what lets `make audit` report a layer as BLOCKED with a
reason instead of a build simply producing less.

ONE WRITER. Every node and edge in the graph goes through emit.py.
Schema validation and the provenance requirement are enforced there, so
"an edge with no source" is not a thing a new layer can accidentally
create. A second writer would be a second place for those rules to be
half-applied.

NORMALISATION HAPPENS AT INGEST, NOT AT QUERY TIME.
    normalize_chem   any structure representation -> a stable node key:
                     an InChIKey plus a 14-character skeleton that
                     groups salts, stereoisomers and tautomers together.
    normalize_bio    UniProt secondary -> primary accessions, taxa,
                     MONDO terms. These are lookup problems, and their
                     failure mode is SILENT: a source cites a secondary
                     accession, the lookup misses, and the edge vanishes
                     with no error.
    aliases          an identifier the graph chooses not to keep as a
                     node must still RESOLVE. Sources cite the ids they
                     cite, and a dropped identifier fails silently.

THE SCHEMA IS DATA, NOT CODE. schema.py loads one declaration of node
classes, predicates, required qualifiers, held-out flags and metapaths.
Metapaths in particular are DECLARED rather than written as queries, so
each route's reach and performance can be measured separately and a
route cannot quietly change shape between the evaluation and the agent.

PROVENANCE IS A STAGE, NOT A FIELD. provenance.py computes a release
fingerprint (content hashes of nodes.jsonl and edges.jsonl), stamps
every results file with it, and audits them back. check_results.py walks
data/results and fails anything that no longer describes the graph on
disk, including the derived train/test split that the hard-negative
protocol reads.

THE AGENT IS A FIXED PIPELINE, NOT A LOOP.

    question
      |
      v
    orchestrator.py   classifies intent, resolves the virus, and runs a
      |               FIXED sequence. A model that decides its own next
      |               action is non-deterministic by construction, and a
      |               researcher who runs the same query twice and gets
      |               two answers cannot cite the tool. Per-step
      |               reliability also compounds: five chained decisions
      |               at 90% each leave 59%.
      v
    guards.py         refusals and caveats, BEFORE retrieval. Refuses
      |               prospective candidate generation outright, refuses
      |               a virus with no feature route, and attaches the
      |               thin-route and not-validated caveats.
      v
    tools.py          parameterised graph tools. The model never writes
      |               a traversal: a malformed query returns an empty
      |               result, an empty result is indistinguishable from
      |               "no evidence exists", and the model then reports
      |               the latter. Every tool is a fixed function with
      |               typed parameters and a bounded output.
      v
    llm.py            the only stage a model writes prose in.
      |
      v
    verify.py         a separate stage with a fresh context, and MOSTLY
                      NOT A MODEL: citation ids are checked against the
                      edges retrieved, numbers against the facts they
                      claim to quote, and every mandatory caveat's label
                      must survive into the answer or the answer is
                      discarded. Self-critique inside one context is
                      weak, because the model is checking work it has
                      already committed to.

DIRECTORY LAYOUT

    config/           viruses.yaml (the register), schema, ORCS polarity
                      overrides
    src/kgav/         28 modules: one per source layer, plus schema,
                      assemble, emit, provenance, normalisation,
                      baselines, calibration, temporal, landscape
    src/kgav/agent/   orchestrator, guards, tools, verify, llm
    scripts/          57 entry points: 12 ingests, the assembler, the
                      evaluation protocols, the diagnostics, the audits
    tests/            the gate; every figure in docs/ that a rebuild
                      could move is re-derived here
    data/raw/         sources as they arrived            (gitignored)
    data/releases/    assembled graphs                   (gitignored,
                      except MANIFEST.json and the smoke release)
    data/results/     every measured figure              (TRACKED, on
                      purpose: a result that exists only on the machine
                      that produced it is not evidence for anything)
    docs/             this report, and evaluation.md


================================================================================
3. SCHEMA SPECIFICATION
================================================================================

11 node classes:

    SmallMolecule     a compound, keyed on InChIKey skeleton
    Protein           viral or host, keyed on UniProt accession or chain
    TargetClass       a protein family / fold class
    Gene              viral or host
    OrganismTaxon     a virus (or host) at NCBI Taxonomy
    VirusStrain       a named strain, for resistance
    Disease           a MONDO term
    Variant           a sequence variant
    Pathway           a Reactome pathway
    CellLine          a Cellosaurus line, for assay context
    Publication       a PMID

24 predicates. Direction is subject -> object.

    CHEMISTRY
      INHIBITS                      SmallMolecule -> Protein     (viral)
      TARGETS                       SmallMolecule -> Protein     (host)
      MEASURED_INACTIVE_AGAINST     SmallMolecule -> Protein     HELD OUT
      CHEMICALLY_SIMILAR_TO         SmallMolecule -> SmallMolecule  symmetric
      COMBINED_WITH                 SmallMolecule -> SmallMolecule  symmetric

    VIRAL SPINE
      ENCODED_BY                    Protein -> Gene
      BELONGS_TO                    Gene -> OrganismTaxon
      HAS_STRAIN                    OrganismTaxon -> VirusStrain
      SUBCLASS_OF                   OrganismTaxon -> OrganismTaxon
      CAUSES                        OrganismTaxon -> Disease
      CONFERS_RESISTANCE_TO         VirusStrain -> SmallMolecule

    HOST BIOLOGY
      HOST_FACTOR_FOR               Protein -> OrganismTaxon
      PHYSICALLY_INTERACTS_WITH     Protein -> Protein           symmetric
      PARTICIPATES_IN               Protein -> Pathway
      HAS_VARIANT                   Gene -> Variant
      OCCURS_IN                     Variant -> Protein

    STRUCTURE
      MEMBER_OF_CLASS               Protein -> TargetClass
      FOLD_SIMILAR_TO               Protein -> Protein           symmetric

    LABELS (all HELD OUT)
      HAS_ANTIVIRAL_ACTIVITY_AGAINST  SmallMolecule -> OrganismTaxon
      TREATS                          SmallMolecule -> Disease
      IN_TRIAL_FOR                    SmallMolecule -> Disease

    IDENTITY AND OUTPUT
      SUBCLASS_OF_DISEASE           Disease -> Disease
      SAME_AS                       any -> any                   symmetric
      PREDICTED_INDICATION          SmallMolecule -> OrganismTaxon  model output

EVERY EDGE CARRIES PROVENANCE. primary_knowledge_source is required and is
an infores identifier; evidence_tier and first_asserted_date are required.
The schema validates this on ingest, so an edge without a source cannot
enter the graph. Qualifiers carry the measurement context that makes an
edge interpretable — assay_type, direction, screen_type, cell_line, ic50_nm,
target_resolution, detection_method, pmid.

HOST_FACTOR_FOR.direction is the qualifier that matters most. A CRISPR
screen reports a gene whose loss changes infection, and the SIGN decides
the meaning: direction=dependency means the virus needs it, so inhibiting
it is a candidate therapy; direction=restriction means the host uses it to
fight the virus, so inhibiting it would be actively harmful. Every
pathway and host-directed metapath constrains on direction=dependency.
Getting that sign backwards is the one error in this graph that produces
a confidently wrong recommendation rather than a missing one.

4. RELEASE CENSUS
================================================================================

    docs/kg_release_census.txt

GENERATED, NOT WRITTEN, AND IN ITS OWN FILE. It is produced by
scripts/write_kg_report.py from the assembled release and stamped with
the content hashes of nodes.jsonl and edges.jsonl -- the same hashes
`make check-results` audits every results file against. A rebuild
without a regenerate leaves a census whose stamp no longer matches the
graph, and `make kg-report-check` reports it; so does a missing file,
because absent is not the same as fine.

    make kg-report          # regenerate
    make kg-report-check    # fail if stale or missing, write nothing

It lived inside this report between two markers until 2026-10-29. The
generated block and the prose around it have different lifecycles --
one changes on every rebuild, the other on every correction -- and
sharing a file guaranteed they collided: twice, a regenerated census
left uncommitted stopped the next correction from applying at all.

WHAT IT REPORTS, and why each part is there.

  THE STAMP        release name, nodes_sha, edges_sha. Without these a
                   count is a number with no graph attached, which is
                   how this project twice shipped a figure describing a
                   release that no longer existed.

  TOTALS           nodes and edges, with the per-class and
                   per-predicate counts reconciled against them. If
                   they ever fail to sum, the census says so rather
                   than printing a figure that looks whole.

  NODES BY CLASS   every class the SCHEMA declares, including the ones
                   holding zero, with the empty ones named. Listing
                   only what is present reports presence and stays
                   silent on absence, which is the thing this project
                   refuses everywhere else.

  EDGES BY         likewise every declared predicate, with the held-out
  PREDICATE        ones flagged -- and an absent EVALUATION LABEL
                   called out as one, because a label predicate with no
                   edges changes how every result in docs/evaluation.md
                   should be read.

  EDGES BY         curators, not source strings.
  CURATOR          primary_knowledge_source is a "|" separated list
                   once an edge has been merged, because one fact can
                   have several witnesses; counting raw values reported
                   35 "sources" for 13 real curators. An edge with
                   several counts once for each, so the column sums to
                   more than the edge total and says by how much. A
                   REPEATED curator inside one value is flagged
                   separately, because it is the footprint of an
                   assembler defect rather than a property of the
                   evidence, and collapsing it for display would hide
                   that the release predates the fix.

  LAYERS           which of the twelve were assembled, and the hub cut
                   degree the assembly used.

The per-virus breakdown of these totals is `make audit`, which also
reports what each layer contributed and what is missing.


================================================================================
5. DATA SOURCES — WHAT WAS USED AND HOW
================================================================================

UniProt                                            infores:uniprot
    The viral spine and the host proteome. Reviewed human proteome gives
    Protein and Gene nodes. Per-virus reference proteomes give the viral
    side.
    POLYPROTEIN EXPANSION is the real work here. Coronavirus replicase is
    translated as one polyprotein and cleaved into nsp1-nsp16, so the
    targets that matter — Mpro (nsp5), RdRp (nsp12), helicase (nsp13) — are
    CHAINS INSIDE P0DTD1, not separate accessions. Flaviviruses are the
    same: one polyprotein cleaved into C-prM-E-NS1-NS2A-NS2B-NS3-NS4A-
    NS4B-NS5. Without expanding chains the direct-acting channel has
    nothing to point at. The register records, per virus, which accession
    carries the chains.
    Also the source of PARTICIPATES_IN: UniProt's own Reactome and GO
    cross-references are read rather than Reactome being ingested
    separately, so pathway membership inherits UniProt's mapping decisions
    and its release stamp.

NCBI Taxonomy                                infores:ncbi-taxonomy
    OrganismTaxon identity. The register pins each virus to one taxid, and
    this matters because curation disagrees: ChEMBL files some activities
    under a parent taxon ("Dengue virus", "Flavivirus") and some under
    strain-level taxa ("Yellow fever virus strain 17D"). The register
    declares which taxa belong to which virus so an ingest cannot silently
    drop rows or merge two viruses.

MONDO                                               infores:mondo
    Disease nodes and CAUSES edges, for all 16 viruses. Each term is
    verified live by scripts/verify_mondo.py, which also checks the term
    was reached by the cross-reference its mondo_source names — a
    label-string match is not accepted as a basis, and a MONDO id citing
    itself is rejected.
    The four dengue serotypes share MONDO:0005502 and the four endemic
    human coronaviruses share MONDO:0005709, which is correct: the disease
    is one entity and the viruses are four.

ChEMBL 37                                           infores:chembl
    The chemistry, and four different things come out of it.
      INHIBITS                        compound -> viral protein
      MEASURED_INACTIVE_AGAINST       compound -> viral protein   (held out)
      TARGETS                         compound -> human protein
      HAS_ANTIVIRAL_ACTIVITY_AGAINST  compound -> virus           (held out)
    The split between the first and the last is the assay READOUT, not the
    source. An activity measured against a purified protein is
    protein-level evidence; an activity measured as cytopathic effect in
    cells is organism-level and is a LABEL. 1,884 of 7,677 protein-target
    rows (24.5%) described a cellular readout while being filed against a
    viral protein, and are now reattributed to the organism. Every INHIBITS
    edge carries target_resolution recording how the chain was identified.
    ChEMBL also supplies the SELECTIVITY layer, from same-document
    EC50/CC50 pairs. An earlier version of this project recorded that
    ChEMBL holds almost no cytotoxicity data for coronaviruses — 2 CC50
    records. That was a query error, not a database fact: cytotoxicity is
    filed against the CELL LINE it was measured in, not the virus, so a
    search restricted to viral organism targets finds nothing.

STRING v12.0                                        infores:string
    The host interactome, which is what gives network proximity a distance
    to measure.
    THE THRESHOLD IS NOT THE CONVENTIONAL ONE, deliberately.
    combined_score >= 700 is conventional and keeps ~474k human edges —
    but 60% of those have experimental < 400 and clear the bar on
    text-mining and co-expression, while ~120k edges with strong
    experimental support fall below 700 and would be discarded.
    Text-mining co-occurrence measures how often two proteins are written
    about together, which tracks study volume rather than binding. For a
    proximity baseline, where distance through the interactome IS the
    quantity of interest, that inflates closeness around well-studied
    proteins and makes the score partly a measure of literature volume.
    So the filter is experimental >= 400 (~309k edges). Every channel
    score is kept as an edge qualifier, so the combined>=700 variant is
    reconstructible by query rather than by re-ingest, and both can be
    reported as a sensitivity analysis.

VirHostNet                                      infores:virhostnet
    Virus-host physical interactions, in PSI-MITAB 2.7. This is the layer
    that makes the graph antiviral rather than generic: it is the only
    bridge between the viral spine and the host interactome, so metapath
    M3 exists entirely because of it.
    Attribution is read from MITAB column 12 (source database), not from
    the file it arrived in, because one PSICQUIC endpoint serves rows
    curated elsewhere. A row VirHostNet serves but IntAct curated is
    attributed to IntAct.
    The evidence is dominated by proximity-dependent biotin
    identification (MI:1314) and affinity capture rather than by binary
    methods, which is recorded on each edge and surfaced as a caveat: a
    BioID hit means "in the same neighbourhood", not "binds".

IntAct, MINT, DIP, HPIDb          infores:intact, infores:mint,
                                  infores:dip, infores:hpidb
    The other virus-host PPI curators, reached through PSICQUIC and
    attributed by the same column-12 rule rather than by the endpoint
    that served them. MINT and DIP rows arrive through the IntAct and
    VirHostNet endpoints and are attributed to MINT and DIP; a row
    co-curated by HPIDb is attributed to it.

    THEIR NAMES ARE NEVER LITERALS IN THIS CODEBASE. They are slugged
    at runtime from the curator's own name in MITAB column 12, so a
    source survey that greps the source tree cannot see them -- and an
    earlier version of this report listed HPIDb among the endpoints
    that "returned nothing usable" while the release carried its edge.
    The release census in section 4 is the only place these names
    appear, and a test now requires every source it shows to be
    described here.

    IMEx is absent from that list on purpose: it is an aggregator, and
    on this query its rows are IntAct's.

BioGRID ORCS                                 infores:biogrid-orcs
    CRISPR screen host factors — HOST_FACTOR_FOR with direction. The
    densest repurposing signal in the graph and the only layer where a
    sign error produces a confidently wrong recommendation. Polarity is
    determined per screen rather than assumed, with manual overrides
    recorded in config/orcs_polarity_overrides.json.

NCATS OpenData                             infores:ncats-opendata
    The SARS-CoV-2 cytopathic-effect screen AND its host-toxicity
    counterscreen. Both, because a compound that reduces CPE by killing
    the cells is not an antiviral, and the counterscreen is what
    distinguishes them. Used as an independent label source, which is why
    the final hard-negative protocol is run with
    --label-source infores:ncats-opendata.

InterPro                                          infores:interpro
    Target classes and fold assignments, feeding MEMBER_OF_CLASS and
    FOLD_SIMILAR_TO. The fold layer found that all three virus families'
    proteases SHARE a fold — the original assumption that they differ was
    wrong. What separates them is the catalytic nucleophile, read from
    UniProt's annotated active site: cysteine in coronaviruses and
    picornaviruses, serine in flaviviruses. FOLD_SIMILAR_TO therefore
    carries catalytic_type_match, and the cross-family metapath is gated
    on it.

Guide to PHARMACOLOGY                 infores:guidetopharmacology
    A second drug -> human protein TARGETS source. NOT BUILT on this
    release: the download requires registration and the files are absent.
    The layer is implemented and will run when they are placed.

Curated published screens                 infores:curated-screen
    Host factors from papers BioGRID ORCS does not carry. ORCS supplies
    flavivirus screens for DENV-2, Zika and West Nile and nothing for
    DENV-1, DENV-3, DENV-4, JEV or TBEV. NOT BUILT on this release:
    data/raw/curated_screens/*.tsv is absent and the provenance of a
    hand-placed screen file has to be established before it can be
    trusted.

kgav itself                                 infores:kgav-computed
    Edges this project derives rather than reads: CHEMICALLY_SIMILAR_TO
    (Tanimoto over Morgan fingerprints), and SAME_AS identity edges. Marked
    as computed so a derived edge is never mistaken for a curated one.

SOURCES SURVEYED AND DELIBERATELY NOT USED
    BioGRID (PSICQUIC)  keys on Entrez Gene / LocusLink identifiers, not
                        UniProt accessions, so its rows cannot be joined
                        to this graph's proteins. 0 usable rows. Not
                        ingested, and recorded as unreadable rather than
                        as having no data — those are different claims.
    IMEx                fully redundant with IntAct on this query (differs
                        by ~10 edges). Ingesting both would double-count.
    NDEx                the VirHostNet network published there is a 2021
                        PSICQUIC dump of the same source, older than the
                        live endpoint.
    InnateDB, MPIDB, UniProt and Reactome PSICQUIC endpoints
                        returned nothing usable for these taxa.

    DENV-4 and Yellow fever have NO curated virus-host PPI in any of the
    ten sources surveyed. That is a property of the literature, not of
    this ingest.

6. BUILD PIPELINE — 12 LAYERS
================================================================================

Each layer is an independent ingest writing its own release directory, and
assemble.py merges them under a declared precedence. A layer that cannot
run is reported as blocked rather than skipped silently.

  PHASE 1 — structure and primary evidence
    spine         required   viral taxa, genes, chain-expanded proteins,
                             disease nodes                      [UniProt,
                             NCBI Taxonomy, MONDO]
    host          required   human proteome, pathway membership, host
                             interactome                   [UniProt, STRING]
    vhppi         optional   virus-host physical interactions
                                           [VirHostNet, IntAct, MINT]
    orcs          optional   CRISPR host factors with direction
                                                        [BioGRID ORCS]
    curated       optional   host factors from published screens   NOT BUILT
    chembl        optional   viral-target chemistry and antiviral labels
    hosttargets   optional   drug -> human protein TARGETS         [ChEMBL]
    ncats         optional   CPE screen plus host-toxicity counterscreen
    folds         optional   target classes and fold similarity  [InterPro]

  PHASE 3 — derived and secondary
    selectivity   optional   selectivity index from same-document
                             EC50/CC50 pairs                      [ChEMBL]
    similarity    optional   CHEMICALLY_SIMILAR_TO cold-start edges
                                                         [kgav-computed]
    gtop          optional   second TARGETS source                 NOT BUILT

WHY hosttargets IS A SEPARATE LAYER. After the chemistry layer first ran,
the graph held thousands of HOST_FACTOR_FOR edges and ZERO TARGETS edges,
because only activities against coronavirus targets had been ingested.
That left five of the eight metapaths with nothing to traverse: every
host-directed route starts with a drug targeting a HUMAN protein.

PROVENANCE DISCIPLINE. Every results file carries the release it was
computed against, by content hash of nodes.jsonl and edges.jsonl.
`make check-results` compares all of them to the graph on disk and fails
any that no longer describe it, including the derived train/test split
that the hard-negative protocol reads. A figure computed from a graph
that no longer exists is reported as stale rather than quoted.

AND THE GRAPH ITSELF IS REPRODUCIBLE, WHICH IT WAS NOT UNTIL
2026-10-29. That sentence is the whole of this paragraph's content and
it could not have been written the day before.

  WHAT WAS WRONG. Assembly.write emitted dict values in insertion
  order and release_fingerprint hashes those bytes, so a release had
  no canonical form: the same graph could serialise two ways. And
  similarity_edges chose its top-k neighbours with `sort(key=-sim)`
  and no tie-break -- a stable sort, so tied neighbours kept the order
  of a dict built from a SET, and string hashing is randomised per
  process. When a tie straddled the cut, which neighbour survived
  depended on the hash seed.

  HOW IT LOOKED. Four builds of v0.1 from identical raw inputs, with
  every raw checksum verified and no build-path code change between
  them, produced four edges_sha values: a9a68fe6a41380c6 (2026-10-28),
  then 2f51efb4f897538e, 3152d60b40c7a5d2 and 7587762b38eea391 on
  2026-10-29. nodes_sha was identical across all four, which read as
  evidence that nodes were safe; it was luck, since nothing ordered
  them either. The real difference was 8 to 10 CHEMICALLY_SIMILAR_TO
  edges out of 389,306, swapped one for one, totals unchanged.

  WHY NOTHING CAUGHT IT. check_results compares results against the
  release ON DISK and never against a rebuild, and the release
  recorded no commit to compare HEAD against. Nothing in the pipeline
  asked the question, and no one had rebuilt v0.1 since assembling it.

  WHAT IS TRUE NOW. Records and keys are both sorted on write, so one
  graph has one byte form. The top-k tie is broken on the neighbour's
  id -- arbitrary, and chosen because it is a property of the content.
  MANIFEST.json carries the commit that assembled the release, and
  check_results says when that is not HEAD. Two consecutive full
  builds have been compared edge by edge and are byte-identical:
  130,449,080 bytes, 389,306 edges, nothing differing.

  WHAT IS STILL UNEXPLAINED. The 2026-10-28 release carried 542 edges
  whose primary_knowledge_source named one curator twice; a rebuild of
  the same pre-dedup code the next day produced 568. Both are
  PHYSICALLY_INTERACTS_WITH, a layer neither fix above touches, and
  the two 2026-10-29 builds agree with each other on it. The release
  that would settle it was overwritten before anyone thought to keep
  it. Recorded as an unexplained historical discrepancy rather than
  resolved, and it is not ongoing.


================================================================================
7. METAPATHS
================================================================================

8 reasoning routes, declared in the schema rather than written as
queries, so each one's reach and performance can be measured separately.

  M1  direct-acting
      Drug -INHIBITS-> ViralProtein -ENCODED_BY-> Gene -BELONGS_TO-> Virus
      Constrained on target_resolution, so a chain identified only by an
      assay description is distinguishable from one resolved properly.

  M2  host-directed, single hop
      Drug -TARGETS-> HostProtein -HOST_FACTOR_FOR-> Virus
      direction=dependency.

  M3  host-directed via virus-host PPI
      Drug -TARGETS-> HostProtein -PHYSICALLY_INTERACTS_WITH->
      ViralProtein -ENCODED_BY-> Gene -BELONGS_TO-> Virus
      Exists only because of the vhppi layer.

  M4  PATHWAY-MEDIATED
      Drug -TARGETS-> HostProtein -PARTICIPATES_IN-> Pathway
      <-PARTICIPATES_IN- HostProtein -HOST_FACTOR_FOR-> Virus
      direction=dependency, hubs excluded. This is the pathway-analysis
      route: a drug reaches a virus because it hits a protein sharing a
      pathway with something the virus depends on.

  M5  host PPI-mediated
      Drug -TARGETS-> HostProtein -PHYSICALLY_INTERACTS_WITH->
      HostProtein -HOST_FACTOR_FOR-> Virus
      direction=dependency, hubs excluded.

  M6  cold start via chemical similarity, host-directed
      Drug -CHEMICALLY_SIMILAR_TO-> Drug -TARGETS-> HostProtein
      -HOST_FACTOR_FOR-> Virus
      direction=dependency.

  M7  cold start via chemical similarity, direct-acting
      Drug -CHEMICALLY_SIMILAR_TO-> Drug -INHIBITS-> ViralProtein
      -ENCODED_BY-> Gene -BELONGS_TO-> Virus

  M8  cross-family direct-acting via conserved fold
      Drug -INHIBITS-> ViralProtein -FOLD_SIMILAR_TO-> ViralProtein
      -ENCODED_BY-> Gene -BELONGS_TO-> Virus
      Gated on catalytic_type_match, so a cysteine-protease inhibitor is
      not transferred to a serine protease on fold similarity alone.

HUB EXCLUSION on M4 and M5 is not cosmetic. Without it, every drug
reaches every virus through ubiquitin or a ribosomal protein, and the
score measures connectivity rather than biology.

8. HOW THE GRAPH SUPPORTS PATHWAY ANALYSIS
================================================================================

Three distinct capabilities, in increasing order of what they claim.

(a) COMPOUND-CENTRED PATHWAY CENSUS — descriptive, no model.
    THIS IS THE ONE THE AGENT ANSWERS. Given a compound and a virus, it
    reports how many human targets the compound has, how many pathways
    under the member cap contain at least one of them, and how many of
    those contain a protein the virus depends on — each with the
    pathway's size, which of the compound's targets sit in it, and which
    of its members are dependency factors. A join over TARGETS,
    PARTICIPATES_IN and HOST_FACTOR_FOR (direction=dependency). It needs
    no labels and no scorer, so none of the label-confound problems
    apply.

    NEVER THE COUNT ALONE. A larger pathway contains a dependency factor
    more often for no reason but its size, so the census is reported
    against a SIZE-MATCHED background expectation and the ratio between
    them, with a tail probability on the excess — and that probability
    is stated to be anti-conservative, because pathways overlap and
    share members, so the independence the tail assumes does not hold.

    AND THREE THINGS IT REFUSES TO IMPLY. Membership is not benefit:
    most TARGETS edges record potency with no direction, so a compound
    may activate a protein the virus depends on as easily as inhibit it.
    The measured null rides along, so a hit is context rather than
    evidence. And a direct-acting antiviral with no human target is
    reported as having none BECAUSE OF WHAT IT IS, not because the
    source is thin — those are different statements and the graph knows
    which applies.

    WHAT IT DOES NOT DO. The agent never walks M4. tools.pathways is a
    census, not a metapath traversal, so there is no pathway-mediated
    RANKING: M4 exists in the schema and in the evaluation and not in
    an answer.

    AND THE VIRUS-ONLY FORM, tools.virus_pathways. Asked which
    pathways a virus depends on with no compound named, the
    orchestrator routes to it rather than falling through to a node
    profile. It takes that virus's dependency factors — HOST_FACTOR_FOR
    with direction=dependency, the restriction factors excluded — and
    counts how many sit in each Reactome pathway. In layman's terms:
    of the human proteins this virus needs in order to replicate,
    which cellular processes are they clustered in.

    IT REPORTS NO P-VALUE, AND THAT OMISSION IS THE DESIGN. The
    pathways it ranks are selected BY the dependency set and then
    scored ON the same dependency set: selection and outcome are one
    event, so a tail probability computed there measures the procedure
    rather than the biology. What it reports instead is the observed
    member count beside a size-matched expectation and the ratio
    between them, ordered twice — once by dependency count, which
    favours large pathways, and once by density ratio over pathways
    expected to hold at least one member, which does not. Both
    orderings are printed because each is wrong in a way the other
    corrects, and the first version of this tool printed only the
    first, which is the bias the ratio exists to fix.

    AND IT MARKS PATHWAYS NAMED AFTER THE VIRUS. Reactome curates
    virus-specific pathways — "SARS-CoV-2 modulates autophagy" is one,
    and it ranked near the top of the first run — from that virus's
    own literature, which is the literature the host-factor screens
    come from. Such a pathway
    scores high because of where its members were found rather than
    because of what they do. Each is tagged [NAMES THIS VIRUS] in both
    lists, and marked rather than dropped: the membership is real, and
    a reader who knows why the number is high can still use it.

    WHAT IT IS NOT. A census, like its compound-centred sibling, not a
    test. A high ratio says a cluster exists; it does not say the
    cluster is druggable, nor which direction a drug would have to
    push it. An earlier version of this section said "for any virus,
    the graph can list the Reactome pathways its dependency factors
    sit in ... the agent exposes it as a PATHWAY query" at a time when
    the agent did not. The claim is true now. In between it was
    carried as a gap in section 10, which is where a capability this
    project does not yet have belongs.

(b) CROSS-VIRUS PATHWAY COMPARISON — descriptive, and NOT EXPOSED.
    Because all 16 viruses hang off one host proteome with one pathway
    vocabulary, the same census is comparable across viruses and across
    families in principle: "which pathways do flaviviruses depend on
    that coronaviruses do not" is a set operation over the graph, and
    the answer would carry each edge's screen, cell line and
    publication. No tool and no query performs it today. It is written
    here as what the DATA supports, not as something the agent can be
    asked.

(c) ENRICHMENT — inferential, and the part that must be done carefully.
    scripts/pathway_landscape.py asks whether a virus's dependency
    factors are over-represented in particular pathways. It reads only
    TARGETS, PARTICIPATES_IN and HOST_FACTOR_FOR and never touches a
    label predicate, so the shared-publication confound that defeated the
    compound-ranking evaluation has nothing to attach to.

    THE CONFOUND MOVES RATHER THAN VANISHING, and this is the single most
    important methodological point in this file. Well-studied proteins
    carry more pathway annotations, are likelier to be drug targets, AND
    are likelier to come out of a CRISPR screen with enough coverage to
    be called a dependency factor. An over-representation test against
    the whole proteome measures study volume, not biology.

    So every enrichment is reported twice: naive, and against a
    background sampled to match the observed degree distribution. The
    gap between the two is a measurement, not a footnote.

    Two channels ask it two ways. The TAXA channel takes dependency
    factors asserted directly against the organism. The INTERACTOME
    channel takes the host partners of viral proteins, which is a larger
    and much softer set.

    RESULT ON RELEASE v0.1, run 2026-10-28, degree_basis=study, 2,000
    permutations, seed 0: 22 rows tested, 44 tests with both directions,
    Bonferroni alpha 0.00114. ZERO rows clear it. The uncorrected version
    of the same test would have reported four. DENV-1's interactome
    overlap is p=0.0029 naive and 0.0600 degree-matched; DENV-2's is
    0.0005 and 0.1499. Neither number moved because the data changed.
    docs/evaluation.md holds the full table, machine-checked against the
    results file.

    An earlier run of this binned against the whole graph, which is
    circular — the background included the proteins under test — and
    produced a uniform, confident-looking depletion across every virus.
    That finding was an artifact and is retracted.

WHAT PATHWAY ANALYSIS HERE DOES NOT CLAIM. Not that viral dependency
factors are unstructured: a test that reaches half the register and
rests on six interaction partners for one of its rows is not positioned
to say so. Not that Reactome is the wrong decomposition. The claim is
narrower and it is a real result: on this release, with this null, no
pathway-level enrichment survives correction, and the honest-looking
uncorrected version is an artifact of protein popularity.

9. PER-VIRUS STATE — WHAT EACH VIRUS CAN SUPPORT
================================================================================

From `make audit`, release v0.1, 2026-10-28. Four tiers, and the
distinction between them is the point: they are not degrees of weak
evidence, they are different kinds of absence.

  EVALUABLE (8) — labels present, a route present, and the route reaches
  at least one held-out positive.
      SARS-CoV-2, SARS-CoV, MERS-CoV, HCoV-229E, HCoV-OC43,
      DENV-2, West Nile, Zika

  ROUTES REACH NO LABEL (5) — a metapath terminates at the virus and
  walks it, and reaches NONE of the held-out positives. A ranking for
  these is complete and nothing in this graph can mark it right or wrong.
      DENV-1, DENV-3, HCoV-NL63, JEV, TBEV

  LABELS, NO FEATURE ROUTE (2) — antiviral measurements exist and no
  metapath terminates at the virus. Every prediction is a miss by
  construction. The agent REFUSES to rank these.
      DENV-4 (312 labels), Yellow fever (1,030 labels)

  FEATURES, NOTHING TO SCORE (1) — routes exist, no label exists.
      HCoV-HKU1

THE AGENT ENFORCES THIS. src/kgav/agent/guards.py refuses EXPLAIN,
TRIAGE and PATHWAY queries for a virus with no feature route, naming the
label count and stating that the refusal is "not because no compound
looks promising, but because none can be reached" — because an empty
ranking reads as the former. Below 25 edges a route is allowed with a
THIN ROUTE caveat. Reliability is reported from the virus's own
calibration, and on this release NO virus has a channel whose interval
clears chance, so every answerable virus carries VIRUS NOT VALIDATED.

AND THE ENFORCEMENT ONLY REACHES QUESTIONS IT RECOGNISES, which is a
separate problem from whether the refusal is correct. classify_intent
is keyword-based on purpose — a model asked to classify intent will
occasionally route a prospective question into a permitted category,
and this refusal must not be probabilistic. But a keyword list leaks:
"which drug should" was on it and "which compounds should" was not, so

    which compounds should be considered for Yellow fever

classified UNKNOWN, fell through the orchestrator's catch-all, and
returned a PROFILE of the taxon node listing 1,030 antiviral
measurements — for the virus in the tier this refusal was written for.
The refusal text existed, was correct, and was never reached. Fixed
2026-10-29 with a structural backstop: a candidate-seeking noun plus a
seeking word, evaluated LAST so every explicit branch matches first,
and FAILING CLOSED. A wrongly refused question is a nuisance; a
wrongly answered one puts a shortlist in front of someone for a virus
this graph cannot rank.

THE REFUSAL'S CLOSING OFFER IS ROUTE-AWARE for the same reason. The
general prospective refusal ends by naming what the graph CAN do —
explain a mechanism, rank a set you already have — and for a virus in
the LABELS, NO FEATURE ROUTE tier it will decline both. So when the
virus has no route the offer is narrowed to what actually works for it,
and the categorical limit is still stated above it, because a reader
told only that this virus is thin could reasonably conclude a richer
one would be answered.

HOW THIS WAS FOUND, which is the part worth keeping: by running the
agent against one virus from EACH tier above instead of SARS-CoV-2
again. Every earlier hand-check used an EVALUABLE-tier virus, so the
only path ever read by eye was the one where labels, routes and
reachable positives are all present. The refusal branch had unit tests
and had never been read. It failed on the first query.
